MM 기본 T-Code와 흐름 — 자재 · 재고 · 구매 · 입고 · 전표 · BOM

"이 화면은 어디서 여나 / 이 데이터는 어느 테이블에 쌓이나"를 한 장으로
대상: S/4HANA 기준(ECC 차이는 따로 표시) · 도해 9장 · 캡처는 추후 추가

결론부터. MM의 T-Code는 외울 목록이 아니라 하나의 흐름 위의 정거장입니다.

마스터(MM01)를 만들고 → 구매요청(ME51N) → 구매오더(ME21N) → 입고(MIGO 101) → 재고이동(MIGO 311) → 송장(MIRO)으로 흘러갑니다.

정거장마다 문서가 하나씩 생기고, 조회 T-Code는 그 문서를 다시 여는 창입니다. 이 흐름만 잡으면 "어디서 보지?"의 답이 자동으로 나옵니다.

LESSON 1MM 전체 지도 — 정거장과 문서

언제 보나. "입고 내역 어디서 봐요?", "이 PO 송장 들어갔어요?" 같은 질문을 받았을 때입니다.

질문을 흐름 위의 어느 정거장인지로 바꾸면 T-Code와 테이블이 같이 떠오릅니다. 반대로 T-Code만 외우면, 비슷한 조회 화면 사이에서 계속 헤맵니다.

T-Code 이름 짓기 규칙 — 끝자리만 보면 된다

MM의 T-Code는 대부분 생성 · 변경 · 조회가 1 · 2 · 3으로 짝지어 있습니다. 하나만 알면 나머지 둘은 따라옵니다.

LESSON 2자재마스터 — 생성 · 변경 · 조회 · 삭제

언제 쓰나. 모든 MM 거래의 출발점입니다. 자재가 해당 플랜트 · 저장위치에 확장돼 있지 않으면 PO도, 입고도 안 됩니다.

안 하면 뭐가 터지나. MIGO에서 M7 001류 "자재 ○○이(가) 플랜트/저장위치에 없음" 오류가 납니다. 초보가 가장 먼저 부딪치는 벽입니다.

뷰(View)와 조직레벨 — 어느 뷰가 어느 테이블로 가나

MM01 화면의 탭(뷰)은 그냥 화면 구분이 아닙니다. 뷰마다 저장되는 조직레벨이 다릅니다. 그래서 MM01 첫 화면에서 플랜트 · 저장위치 · 영업조직을 먼저 묻습니다.

"삭제"는 지우는 게 아니다

1

MM06 = 삭제 플래그만 세운다. 데이터는 그대로 남고, 조회도 됩니다. 이후 거래에서 경고나 오류로 막힙니다.

2

실제 물리 삭제는 아카이빙(SARA, 오브젝트 MM_MATNR)으로만 합니다. 재고·미결 문서가 남아 있으면 아카이빙 대상에서 빠집니다.

3

"잠깐 쓰지 마"가 목적이면 삭제 대신 자재상태를 씁니다. 크로스플랜트 상태 MARA-MSTAE, 플랜트 상태 MARC-MMSTA에 구매·입고 차단 상태를 넣으면 되돌리기도 쉽습니다.

4

저장위치 단위로 막으려면 BAdI(유저 엑짓)를 쓴다. 자재상태는 플랜트 레벨까지만 있어서, "이 저장위치로는 입고 금지" 같은 규칙은 표준 설정만으로 만들 수 없습니다.

저장위치별 입출고 제한 — 어디에 끼워 넣나

자재문서 품목이 만들어질 때 호출되는 체크 지점에서 E 메시지를 내면 전기가 막힙니다. 후보는 세 곳이고, 호출되는 경로가 다릅니다.

CHECK_LINE 인터페이스 파라미터(IS_MSEG 등)는 SE18에서 실제 시그니처를 확인하세요. 출하 출고(VL02N 601) 경로에서도 호출되는지는 시스템에서 직접 테스트가 필요합니다.

규칙(저장위치·이동유형 조합)은 소스에 하드코딩하지 말고 Z 설정 테이블이나 TVARVC로 빼 두세요. 구현은 SE19, 기존 구현 확인은 SE18 → 구현 목록.

확인 필요

재고가 남은 자재에 MM06 플래그를 세울 때 경고로 끝나는지, 오류로 막히는지는 시스템 설정·버전에 따라 다릅니다. 실제 시스템에서 재고 있는 자재로 한 번 확인해 두세요.

LESSON 3재고 넣기 · 빼기 — 561 · 551 · 201

언제 쓰나. 테스트용 재고를 만들 때(초기재고 561), 유통기한이 지나 버릴 때(폐기 551), 내부에서 써 버릴 때(소비 201)입니다.

핵심. 재고는 테이블을 직접 고쳐서 넣거나 빼지 않습니다. 반드시 이동유형이 붙은 자재문서로만 움직입니다. 그래야 수량·금액·이력이 같이 맞습니다.

MIGO에서 어떻게 고르나

MIGO는 좌측 상단 액션 + 참조 + 이동유형 세 칸의 조합으로 거의 모든 재고 거래를 처리합니다.

S/4HANA에서 막힌 T-Code

MB1A(출고) · MB1B(이동) · MB1C(기타입고) · MB01(PO입고) · MB31 등 구형 MB 트랜잭션은 S/4HANA에서 사용 중단되고 MIGO로 통합됐습니다(SAP Note 1804812). 인터넷 자료에 MB1C가 보이면 ECC 기준 자료입니다.

LESSON 5구매 — 정보레코드 · PR · PO

언제 쓰나. 벤더에게 물건을 주문하는 모든 경우입니다. PO가 있어야 입고(101)와 송장(MIRO)이 PO를 참조해 자동으로 값을 끌어옵니다.

안 하면 뭐가 터지나. 정보레코드가 없으면 PO마다 단가를 손으로 넣어야 합니다. 사람마다 다른 단가가 들어가고, 이후 가격 비교(정보레코드가 vs 이동평균가)가 불가능해집니다.

LESSON 6입고 · 자재이동 — MIGO와 이동유형

언제 쓰나. 벤더에서 물건이 도착했을 때(101), 돌려보낼 때(122), 창고 안에서 옮길 때(311), 다른 플랜트로 보낼 때(301)입니다.

핵심. MIGO 화면은 하나지만 이동유형이 거래의 성격을 결정합니다. 이동유형이 곧 "재고가 어디서 어디로, 회계는 어떻게"의 설정 묶음입니다.

102 vs 122 — 면접 단골

102는 "입고를 잘못 친 것" 취소(물건은 원래 안 들어온 것처럼)입니다. 122는 "받은 물건을 실제로 돌려보낸 것"이라 반품 사유가 남고, 벤더 평가·출력(반품 납품서)과 연결됩니다.

LESSON 7송장 · 회계전표 — MIRO와 GR/IR

ABAP로 자재별 입고 이력 뽑기

MB51과 같은 데이터를 프로그램에서 읽을 때의 기본형입니다. S/4는 MATDOC 한 테이블, ECC는 MKPF(헤더) + MSEG(품목) 조인입니다.

" S/4HANA — MATDOC
SELECT mblnr, mjahr, zeile, budat, bwart,
       matnr, werks, lgort, charg, menge, meins, ebeln, ebelp
  FROM matdoc
  WHERE matnr = @p_matnr
    AND werks = @p_werks
    AND bwart IN ( '101', '102', '122' )
    AND budat IN @s_budat
  ORDER BY budat DESCENDING
  INTO TABLE @DATA(lt_gr).

" ECC — MKPF + MSEG
SELECT k~mblnr, k~mjahr, s~zeile, k~budat, s~bwart,
       s~matnr, s~werks, s~lgort, s~charg, s~menge, s~meins, s~ebeln, s~ebelp
  FROM mkpf AS k
  INNER JOIN mseg AS s ON s~mblnr = k~mblnr AND s~mjahr = k~mjahr
  WHERE s~matnr = @p_matnr
    AND s~werks = @p_werks
    AND s~bwart IN ( '101', '102', '122' )
    AND k~budat IN @s_budat
  INTO TABLE @DATA(lt_gr_ecc).

" 자재문서 → 회계전표
DATA(lv_awkey) = CONV awkey( |{ ls_gr-mblnr }{ ls_gr-mjahr }| ).
SELECT SINGLE bukrs, belnr, gjahr
  FROM bkpf
  WHERE awtyp = 'MKPF'
    AND awkey = @lv_awkey
  INTO @DATA(ls_fi).
확인 필요

MATDOC에는 자재문서 외에 재고 집계용 레코드도 섞여 있을 수 있어, 레코드 구분 필드 조건이 필요한지 실제 시스템에서 확인하세요. 릴리즈된 CDS 뷰(자재문서 품목 뷰)가 있으면 그쪽을 쓰는 게 권장 방향입니다.

반드시 지킬 것

1. 재고 테이블은 직접 UPDATE하지 않는다

MARD·MCHB·MBEW를 직접 고치면 수량·금액·자재문서·회계전표가 전부 어긋납니다. 프로그램에서는 BAPI_GOODSMVT_CREATE로 자재문서를 만듭니다.

2. 취소는 새 문서다

102·562·MR8M 모두 원래 문서를 지우지 않고 반대 문서를 하나 더 만듭니다. 로그에는 원본과 취소가 둘 다 남는 게 정상입니다.

3. 송장이 들어간 입고는 송장부터 되돌린다

순서: MR8M(송장 역분개) → MBST(입고 취소). 반대로 하면 막히거나 GR/IR 잔액이 꼬입니다.

4. 회계 영향이 있는 이동유형은 자동화 전에 승인 단계를 둔다

551·122·301·MR11은 재고 금액이나 원장을 바꿉니다. CBO로 자동 전기할 때는 알림 또는 승인 대기까지만 두는 게 원칙입니다.

5. S/4HANA에서 MB1A/MB1B/MB1C/MB01은 없다

ECC 자료를 보고 따라 하다가 막히면 MIGO + 이동유형으로 바꿔서 찾으세요.
