FI 기본 T-Code와 흐름 — 원장 · 전표 · 반제 · 자동전기 · 결산

"모든 돈이 모이는 곳"을 한 장으로
대상: S/4HANA 기준(ECC 차이는 따로 표시) · 도해 5장 · 캡처는 추후 추가

결론부터. FI는 "모든 돈의 움직임이 모이는 원장"입니다. MM·SD 거래도 끝은 FI 전표입니다.

전표는 차변 = 대변이어야 저장되고, 벤더·고객 거래는 미결 → 반제로 끝납니다. 이 두 가지와 "원천 문서로 거슬러 올라가는 법(AWKEY)"만 잡으면 개발자가 받는 FI 문의의 대부분을 따라갈 수 있습니다.

LESSON 1FI 전체 지도 — 원장과 보조원장

언제 보나. "이 금액이 왜 이 계정에 있지?"를 추적할 때입니다. MM·SD에서 만든 전표도 결국 전부 FI 원장에 모입니다.

핵심. FI는 총계정원장(G/L) 하나와, 그 아래 거래처·자산별로 쪼갠 보조원장으로 이뤄져 있습니다. 보조원장과 G/L은 조정계정(Reconciliation Account)으로 묶입니다.

조직·기준의미메모
회사코드 BUKRS재무제표를 만드는 법인 단위개인 프로젝트: CL04
계정과목표 KTOPLG/L 계정 목록회사코드에 1개 할당
회계연도 변형기간(월) 정의K4 = 1~12월 + 특별기간 4개
전기기간 변형열린 기간 통제OB52
원장 RLDNR0L 선행원장S/4: 모든 전기가 ACDOCA 한 테이블

LESSON 3전표 전기 — FB50 · FB60 · FB70 · 전기키

언제 쓰나. MM·SD를 거치지 않는 회계 거래를 직접 입력할 때입니다. 비용 전표, 거래처 송장, 대체 전표 등입니다.

핵심. 전표 한 줄 한 줄에는 전기키(Posting Key)가 붙습니다. 두 자리 숫자가 차변/대변과 계정 종류를 동시에 정합니다.

FB70고객 송장 (SD 없이)DR
FB65 / FB75벤더 / 고객 크레딧메모KG / DG
F-02일반 전기 (전기키 직접 입력)자유
FV50 / FV60G/L / 벤더 전표 임시저장Park
전기키차/대계정 종류예

21 / 31차 / 대벤더31 = 벤더 송장, 21 = 벤더 크레딧메모·지급

70 / 75차 / 대자산자산 취득 / 대변

전기키 외우는 요령 — 0x 고객 · 2x/3x 벤더 · 4x/5x G/L · 7x 자산. 앞자리가 계정 종류, 차변·대변 쌍으로 기억합니다.

LESSON 5지급 · 수금 · 반제

언제 쓰나. 벤더에게 돈을 주고, 고객에게 돈을 받고, 그걸 원래 송장과 짝지을 때입니다.

핵심. 반제(Clearing)는 "이 송장은 이 지급으로 끝났다"고 두 항목을 묶는 것입니다. 반제가 안 되면 돈을 줬어도 미결 목록에 계속 남습니다.

T-Code용도메모
F-53벤더 수동 지급미결 항목 선택 → 은행 계정
F110자동 지급 프로그램파라미터 → 제안 실행 → 지급 실행 → 매체 출력
F-28고객 입금입금액으로 미결 선택
F-44 / F-32벤더 / 고객 반제지급 없이 서로 상계
F-03G/L 계정 반제GR/IR · 가계정
FBRA반제 해제반제만 풀고 전표는 유지 → 이후 역분개 가능

LESSON 6역분개 · 임시저장 · 변경

언제 쓰나. 잘못 넣은 전표를 되돌리거나, 검토 전 전표를 저장해 둘 때입니다.

1

역분개는 새 전표다. FB08은 원 전표를 지우지 않고 반대 전표를 하나 더 만듭니다. 역분개 사유(01 당기, 02 차기 등)와 전기일을 지정합니다.

2

반제된 전표는 바로 역분개가 안 된다. FBRA로 반제를 먼저 풀고 FB08.

3

MM·SD에서 만든 전표는 FB08로 되돌리지 않는다. 원천 문서에서 취소해야 합니다 — 입고 MBST, 송장 MR8M, 청구 VF11. FI에서만 되돌리면 MM·SD 문서와 어긋납니다.

4

임시저장(Park)은 회계 영향이 없다. FV50/FV60으로 저장 → 검토 → FBV0로 전기. 임시저장 목록은 FBV3.

T-Code용도메모
FB08전표 1건 역분개역분개 사유 필수
F.80일괄 역분개여러 전표
FBRA반제 해제역분개 전 선행
FBV0임시저장 전표 전기Park → Post
FBV3임시저장 조회
FB02전표 변경텍스트·참조 등 허용 필드만

결산 T-Code는 ECC/S/4와 신·구 G/L 여부에 따라 많이 다릅니다(F.05 → FAGL_FCV, F.16 → FAGLGVTR 등). GR/IR 재분류 방식은 실제 시스템 설정을 확인하세요.

자주 오는 오류

"전기기간 ○○○ 이 계정 유형 ○에 대해 열려 있지 않음" → OB52. MIGO에서 "전기 가능 기간" 오류 → MMPV(MM 기간)부터 확인합니다.

반드시 지킬 것

1. 전표는 BAPI로 만든다

직접 INSERT 금지. BAPI_ACC_DOCUMENT_POST(또는 용도별 BAPI) 사용. 원장·보조원장·세금이 한 번에 맞춰집니다.

2. 원천 문서가 있는 전표는 원천에서 취소

MM·SD 자동 전표를 FB08로 되돌리면 원천 문서와 영원히 어긋납니다.

3. 회계 영향 자동화에는 승인 단계

자동 전기 CBO는 알림 또는 임시저장(Park)까지만 두고 사람이 전기하는 구조가 안전합니다.

4. 전기일과 증빙일을 구분

전기일(BUDAT)은 원장 기간을, 증빙일(BLDAT)은 원본 문서 날짜를 뜻합니다. 기간 오류는 전기일 기준입니다.
