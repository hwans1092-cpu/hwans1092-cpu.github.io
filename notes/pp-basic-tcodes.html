PP 기본 T-Code와 흐름 — MRP · 생산오더 · 확정 · 정산

"무엇을 얼마나 만들고, 만든 원가는 어디로"를 한 장으로
대상: S/4HANA 기준 · 도해 4장 · 개인 프로젝트 범위 밖(제조업 대비용)

결론부터. PP는 "계획 → 생산오더 → 출고 · 확정 · 입고 → 정산"의 흐름이고, 생산오더는 원가를 모으는 그릇입니다.

MRP가 부족분을 계산해 계획오더를 제안하고, 생산오더로 바꿔 릴리즈해야 실제 작업이 시작됩니다. 부품 출고(261)와 확정으로 쌓인 비용이 완제품 입고(101)로 빠지고, 남은 차이를 정산합니다.

LESSON 1PP 전체 지도 — 계획에서 정산까지

언제 보나. 제조업 SAP의 중심입니다. "왜 이 부품 PR이 생겼지?", "이 오더 원가 차이 왜 났지?" 문의가 여기서 옵니다.

핵심. PP는 계획(얼마나 만들까)과 실행(만들고 넣고 정산) 두 줄입니다. 계획오더까지는 제안이고, 생산오더를 릴리즈해야 실제 출고·확정이 가능합니다.

참고

개인 프로젝트(식품 유통 CL04)는 생산이 없는 트레이딩 모델이라 PP를 쓰지 않습니다. 이 노트는 제조업 운영·면접 대비용입니다.

LESSON 4생산오더 — 전환 · 생성 · 릴리즈

언제 쓰나. 계획오더(제안)를 실제 작업 지시로 바꿀 때입니다.

1

계획오더 → 생산오더 전환. 1건은 CO40, 여러 건은 CO41. 수동 생성은 CO01.

2

생성 시 복사. BOM → 부품 예약(RESB), 라우팅 → 공정(AFVC/AFVV), 계획원가 계산.

3

릴리즈(REL). CO02에서 릴리즈해야 출고·확정이 가능합니다. 일괄 릴리즈는 CO05N. 설정에 따라 생성 즉시 자동 릴리즈.

4

가용성 점검. 부품이 모자라면 릴리즈가 막힐 수 있습니다. 오더 안에서 자재 가용성 점검(누락 부품 목록).

반드시 지킬 것

1. 오더 상태를 먼저 본다

출고·확정이 안 되면 대부분 상태 문제(CRTD, TECO, CLSD)입니다. 상태 테이블 JEST/TJ02T.

2. COGI를 비워 둔다

백플러시 오류가 쌓이면 재고·원가가 동시에 틀어집니다. 매일 확인 대상입니다.

3. 오더 생성·확정은 BAPI로

BAPI_PRODORD_CREATE, 확정 BAPI_PRODORDCONF_CREATE_TT 등. 테이블 직접 수정 금지.

4. 마스터 변경은 기존 오더에 반영되지 않는다

BOM·라우팅을 고쳤으면 이미 만든 오더는 "읽기(Read PP master data)"로 다시 불러와야 합니다.
