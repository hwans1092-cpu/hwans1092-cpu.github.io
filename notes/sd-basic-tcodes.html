SD 기본 T-Code와 흐름 — 수주 · 출하 · 청구 · 가격 · 문서흐름

"주문 하나가 돈이 되기까지"를 한 장으로
대상: S/4HANA 기준(ECC 차이는 따로 표시) · 도해 8장 · 캡처는 추후 추가

결론부터. SD는 "수주 → 출하 → 출고 → 청구" 네 문서가 앞 문서를 참조해 이어지는 사슬입니다.

각 문서는 VBFA(문서흐름)로 서로를 가리키고, 출고(PGI)와 청구에서만 MM 재고와 FI 원장에 영향을 줍니다. 이 사슬과 가격결정(조건기법)만 잡으면 SD 문의 대부분의 출발점이 보입니다.

LESSON 1SD 전체 지도 — 정거장과 문서

언제 보나. "이 주문 출고됐어요?", "세금계산서 나갔어요?" 같은 문의를 받을 때입니다.

질문을 흐름 위의 정거장으로 바꾸면 T-Code와 테이블이 같이 떠오릅니다. MM이 "사 오는" 흐름이라면 SD는 "팔고 내보내는" 흐름입니다.

T-Code 이름 규칙 — 1 생성 · 2 변경 · 3 조회

대상생성변경조회비고
판매오더VA01VA02VA03견적 VA21~23 · 조회 리스트 VA05
출하문서VL01NVL02NVL03N일괄 생성 VL10* · 모니터 VL06O
청구문서VF01VF02VF03일괄 VF04 · 취소 VF11
고객BPBPBPECC: XD01/VD01
가격 조건VK11VK12VK13조건 레코드
면접 포인트

"수주를 만들면 회계에 뭐가 남나요?" → 아무것도 안 남습니다. 회계전표는 출고(PGI)와 청구에서 생깁니다. 수주는 여신·가용성 확인과 납기 약속까지입니다.

LESSON 2마스터 — 고객 · 자재 영업뷰 · 판매영역

언제 쓰나. 수주를 넣기 전에 반드시 갖춰야 하는 것들입니다. 고객이 해당 판매영역에 확장돼 있지 않으면 VA01 첫 화면에서 막힙니다.

MM01자재 영업뷰영업: 영업조직 1·2(MVKE), 영업: 일반/플랜트(MARC — 가용성 점검·적재그룹)
VD51고객-자재 정보레코드고객이 쓰는 자재코드 ↔ 우리 자재코드 매핑 (KNMT)
OVX5 등판매조직 정의IMG 설정. 조직 구조는 SPRO → 엔터프라이즈 구조

고객은 만들었는데 VA01에서 "판매영역에 고객 없음"이 나오면 → BP에서 해당 판매영역으로 영업 데이터(KNVV)를 추가하지 않은 것입니다.

LESSON 3수주 — VA01 · 오더유형 · 품목범주

언제 쓰나. 고객 주문을 시스템에 올리는 순간입니다. 이때 가격 결정, 가용성 확인, 여신 체크가 한꺼번에 돌아갑니다.

LESSON 4가격결정 — 조건기법

언제 보나. "왜 이 가격이 들어왔지?" 문의가 오면 가격결정 로직을 따라가야 합니다. SD 개발자가 가장 자주 파고드는 곳입니다.

핵심. SAP은 가격을 "절차 → 조건유형 → 액세스 시퀀스 → 조건테이블 → 조건레코드" 순서로 찾아갑니다. 이 구조를 조건기법(Condition Technique)이라고 하고, 출력·배치결정·품목범주 결정 등에서도 같은 방식이 쓰입니다.

T-Code용도메모
VK11/12/13조건레코드 생성·변경·조회실제 가격·할인 값 입력
VK31/32/33조건 일괄 관리여러 레코드 한 화면에서
V/06조건유형 정의IMG
V/07액세스 시퀀스IMG
V/08가격결정절차IMG
OVKK절차 결정판매영역 + 고객가격절차 + 문서가격절차
확인 필요

S/4HANA에서 가격 결과 테이블이 KONV → PRCD_ELEMENTS로 바뀐 점, 기본 조건유형 명칭(PR00/PPR0)은 시스템에서 실제 가격결정절차를 열어 확인하세요.

LESSON 7문서흐름 · 추적 — VBFA · 상태

언제 보나. "이 주문 어디까지 갔어요?" — SD 운영 문의의 기본 질문입니다. 모든 SD 조회 화면에 있는 문서흐름(Document Flow) 버튼이 답입니다.

T-Code / 테이블용도메모
VA03 → 문서흐름화면에서 추적F5 또는 상단 "문서흐름" 버튼
VBFA문서흐름 테이블선행→후속 한 줄씩
상태 필드진행 상태ECC: VBUK/VBUP · S/4: 상태 필드가 VBAK/VBAP/LIKP/LIPS로 이동
GBSTK · LFSTK · FKSTK전체·출하·청구 상태A 미처리 · B 부분 · C 완료
VA05 · VL06O · VF05단계별 리스트오더 / 출하 / 청구
" 판매오더의 후속 청구문서 찾기
SELECT vbeln, posnn, vbtyp_n
  FROM vbfa
  WHERE vbelv   = @lv_vbeln     " 선행: 판매오더
    AND vbtyp_n = 'M'           " 후속: 청구
  INTO TABLE @DATA(lt_bill).
확인 필요

VBFA는 직접 후속만이 아니라 여러 단계 뒤 문서까지 기록되는 경우가 있습니다(설정·버전별). 체인 추적 로직을 짤 땐 RV_ORDER_FLOW_INFORMATION 같은 표준 FM 사용을 먼저 검토하세요.

반드시 지킬 것

1. 판매문서 테이블을 직접 UPDATE하지 않는다

상태·문서흐름·가격이 전부 연결돼 있습니다. 생성·변경은 BAPI_SALESORDER_CREATEFROMDAT2 / BAPI_SALESORDER_CHANGE 같은 BAPI로.

2. 되돌리는 순서는 만든 순서의 역순

청구 취소(VF11) → PGI 취소(VL09) → 출하 삭제 → 오더 수정. 중간을 건너뛰면 막힙니다.

3. 회계 이전 보류는 매일 본다

VFX3에 쌓인 건은 매출이 원장에 없는 상태입니다. 월말에 발견하면 늦습니다.

4. 가격 문의는 분석 화면부터

조건레코드를 바로 고치지 말고, 오더 가격 분석으로 어느 조건테이블에서 값을 가져왔는지 먼저 확인합니다.
